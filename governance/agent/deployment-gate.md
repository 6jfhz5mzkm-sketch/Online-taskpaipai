# 生产部署规则（部署前确认闸）

> 版本：v1.0 · 2026-09-14 · 状态：**唯一标准**
> 定位：**独立规则文档**（用户 2026-09-14 明确要求：**不写进 `dev-docs/铁律.md`**，单独成文）。
> **何时读**：① 本轮**涉及代码/配置/数据改动**时，开工前读一遍；② **上下文压缩（compact）或换窗口后**恢复工作前读一遍；③ 准备派部署单前逐条对照 §十 自检清单。
> **适用范围**：本机 → 生产的一切变更：商家端 H5、管理后台、`api-py`、nginx 配置、生产库 DDL/DML、生产数据。
> **与其他文档的关系**：`AGENTS.md` §十四 / §十六 第 7 条只保留**指针**；`dev-docs/部署方案-阿里云轻量1gib.md` 只保留**技术执行细节**（构建/备份/切换/验证命令）；**流程闸门的唯一真源 = 本文**。

---

## 一、唯一主线

```
提出变更 → 开发与自测（只在开发环境）
        → 总控汇总「预览就绪」：变更清单 + 预览入口（URL）+ 「看哪里」指引 + 自测证据
        → 用户在开发环境人眼验收 → 明确说「确认 / 可以上线」
        → 总控派部署单（devops）→ 构建 → 备份 → 部署 → 上线后验证 → 记录
```

**一句话**：**没经过用户人眼确认的变更，不许进生产。**

---

## 二、闸门：未确认前禁止做什么

| 禁止项 | 说明 |
|--------|------|
| 上传/替换生产目录 | 包括但不限于 ``<DEPLOY_ROOT>/h5``、``<DEPLOY_ROOT>/admin``、``<DEPLOY_ROOT>/api-py`` |
| 执行生产 DDL/DML | 建表、改表、导数据、改配置行、删数据 |
| 改生产配置 | ``api-py/.env``、nginx 站点配置、systemd unit |
| 重启生产服务 | `merchant-api` / nginx / mysqld |
| 热更生产数据 | 直接改库里的业务数据 |

**允许**：在本机构建产物（无害），但**不得上传**；在本机/开发库做一切验证；产出生产脚本（**只产出，不执行**）。

### 什么**不算**用户确认

- 子 Agent 自测通过、门禁 PASS、构建 EXIT=0；
- 总控判断"看起来没问题""应该没事"；
- 用户说"你先看看""做完我看看"（这是**发起预览**，不是确认上线）；
- 上一批变更的确认（**一次确认只管当轮那一批**）。

---

## 三、预览环境（= 开发环境）

| 端 | 地址 | 备注 |
|----|------|------|
| 商家端 H5 | `http://127.0.0.1:5173/` | uni-app dev server |
| 管理后台 | `http://localhost:5174/` | **只绑 `::1`，必须用 localhost** |
| 后端 | `http://127.0.0.1:8000`（`/health`） | uvicorn，无 `--reload`，代码变更需重启 |

**「预览就绪」必须交付给用户的内容**：

1. **可直接打开的 URL**（不要只说"改好了"）；
2. **本次改了什么**（一句话 + 涉及页面/接口清单）；
3. **「看哪里」的指引**：打开哪个页面、点哪个按钮、看哪个字段的什么变化；
4. **需要登录时的说明**（用哪个账号/怎么进）；
5. **自测证据**（截图/探针输出/接口原始响应）。

**无法人眼预览的变更**（数据/DDL/schema）：
预览 = 在**开发库**演示 + 给出**变更脚本与回滚脚本**（只产出不执行）+ 影响面说明；用户确认后才在生产执行。

---

## 四、确认留痕（四要素，缺一不可派单）

在 `dev-docs/planning/progress.md` 记录：

1. **变更清单**（任务号 + 文件/数据范围）；
2. **预览证据**（URL、截图、探针原始输出）；
3. **用户确认原话**（逐字引用，不得转述成"用户已确认"）；
4. **确认时间**。

四项齐备，才允许派部署单。

---

## 五、确认的粒度

- **一次确认只覆盖当轮那一批变更**，不泛化到后续新变更；
- 确认必须是用户的**明确表述**（如「确认上线」「可以部署」「切吧」）；
- 若当轮变更范围**超出**用户确认时的清单（多改了东西），必须**重新走一遍预览→确认**。

---

## 六、部署阶段的技术要求（派单给 devops 的必含项）

1. **先备份**受影响的生产目录/表：给出字节数 + sha256 + 条目数；备份未完成不得继续；
2. **构建退出码必须显式取**（重定向后读码，禁止只贴日志尾部）；产物自检不得存在**指向 dev 主机的接口地址**（语义判据，不是字符串计数）；
3. **二进制传输**（tar/scp），禁止对产物做文本处理或转码——避免前端乱码；
4. 切换用「**备份 → 清空目录 → 解包**」，禁止覆盖解包（避免新旧产物混杂）；
5. 权限与 owner 与部署前记录一致；**批量 chmod 后必须单独复核 `.env` 仍为 600**；
6. 不改 nginx 配置（静态替换即时生效）；确需改动的先回报等批准；
7. 全程**不得回显口令/密钥**（用 `--defaults-extra-file` / `MYSQL_PWD` / 进程内读取，禁止拼进 argv）；
8. 不扩大范围：只做确认过的变更，构建失败即停并回报。

---

## 七、上线后验证（总控须独立复核，不采信自报）

- 三域名 200 + `/health` 返回后端 JSON；
- **产物一致性**：公网 `index.html` 引用资源集合与本地构建逐条一致、抽检资源 sha256 相同、**旧资源 404**（证明目录已清干净）；
- **编码校验**（用户重点关注）：抓 HTML/JS/CSS 验证合法 UTF-8、已知中文串完整、页面标题不乱码，如实记录 `Content-Type` 的 charset 现状；
- 安全基线：安全头、http→301、服务 active、端口仅 80/443/127.0.0.1:8000、`pm2` 空表；
- 三门禁（结构 / 数据编码 / merchant_id 孤儿），真实目录 `<DEPLOY_ROOT>/api-py`，重定向取退出码（**必须显式取退出码**，见 §六.2）。

---

## 八、回滚

- 每次部署必须留下**回滚资产**（备份包路径 + sha256）与**可直接执行的回滚命令**；
- 静态替换无需 reload nginx；数据库变更须给出逆操作或备份恢复路径；
- **备份必须定期做可恢复性抽查**（把备份还原到临时库并核对关键表行数/抽样字段），**未经演练的备份不算回滚资产**——演练记录见 `dev-docs/部署方案-阿里云轻量1gib.md` **§17.6**（**2026-09-15 `#OPS-37`，结论 = 可恢复**；生产备份为每日 02:00 快照、保留 7 份，**RPO ≈ 24h**）；**备份异地副本已建立**（本机 `_deploy_backups/db/`，拉取脚本 `scripts\backup-pull.cmd`：手动/按需、幂等、本机保留 14 份、失败退出码 1/2/3）——**口径主体见 `dev-docs/部署方案-阿里云轻量1gib.md` §十「本机异地副本」与 §17.6**（本规则只留指针）；
- 回滚命令要**先在本机核对路径真实存在**再写入汇报。

---

## 九、唯一例外（紧急线上故障）

- 线上不可用等紧急情况：可**缩短但不得取消**确认——仍须用户一句明确指令；
- 事后当轮补齐记录：故障现象 / 改动内容 / 验证结果 / 回滚位。

## 十、派部署单前的自检清单

- [ ] 本轮变更有哪些？是否全部在**用户确认的范围**内？
- [ ] 是否已给出**预览 URL + 看哪里 + 自测证据**？
- [ ] 是否已拿到用户**明确确认原话**并记入 `progress.md`（四要素齐备）？
- [ ] 备份资产是否已就绪（路径 + sha256）？回滚命令是否已核过路径？
- [ ] 部署单是否写明了**构建退出码取法 / 产物自检判据 / 权限基线 / 编码校验 / 上线后验证 / 回滚**？
- [ ] 是否明确写了「**不得改 nginx、不得轮换口令、不得 git commit**」等边界？
