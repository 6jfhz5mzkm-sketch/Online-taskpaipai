## 一、版本规划总览

### 1.1 版本节奏

```
V1（4-6周）          V2（4-6周）          V3（4-6周）
入驻准备+开店搭建  →  基础运营           →  营销投放+数据分析
    │                    │                    │
    ▼                    ▼                    ▼
  习惯养成             日常运营              深度经营
```

### 1.2 各版本定位

| 版本 | 阶段覆盖 | 核心目标 | 商家感知 |
|------|---------|---------|---------|
| V1 | 入驻准备（全部一级任务） | 习惯养成 + 数据基建 | "有个任务中心帮我入驻" |

## 四、V2 详细规划（阶段三：基础运营）

### 4.1 任务设计方向

V2从"一次性任务"转向"周期性任务"，帮商家建立日常运营习惯。

### 4.2 任务分类

| 类型 | 示例任务 | 触发条件 | 频率 |
|------|---------|---------|------|
| 商品管理 | 保持每周上架≥3个商品 | 商家上架量低于阈值 | 每周 |
| 服务响应 | 24小时内回复率≥90% | 回复率低于90% | 每日 |
| 发货时效 | 48小时内发货率≥95% | 发货延迟 | 每日 |
| 售后处理 | 退货退款处理时效≤24h | 有退货申请未处理 | 实时 |
| 平台学习 | 学习新的平台规则更新 | 规则更新时 | 按需 |

### 4.3 V2技术实现要点

| 模块 | 技术实现 | 说明 |
|------|---------|------|
| 定时任务 | NestJS @nestjs/schedule | Cron表达式触发周期性任务 |
| 触发条件引擎 | NestJS自定义Service | 根据商家状态动态生成任务 |
| 行为数据采集 | NestJS + MySQL新表 | 采集上架量、回复率等数据 |
| 商家标签 | NestJS + MySQL标签表 | 基于行为数据打标签 |
| 优惠券对接 | NestJS + 拍拍API | 完成任务发放优惠券 |

### 4.4 V2新增数据表

```sql
-- 商家行为数据表
CREATE TABLE merchant_behavior (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    merchant_id     VARCHAR(64),
    behavior_type   VARCHAR(50),
    behavior_value  INT,
    record_date     DATE,
    created_at      TIMESTAMP
);

-- 商家标签表
CREATE TABLE merchant_tag (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    merchant_id     VARCHAR(64),
    tag_name        VARCHAR(50),
    tag_value       VARCHAR(100),
    created_at      TIMESTAMP
);

-- 周期任务配置表
CREATE TABLE periodic_task_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    task_id         VARCHAR(32),
    period_type     ENUM('daily','weekly','monthly'),
    trigger_condition JSON,
    created_at      TIMESTAMP
);
```

## 七、风险和应对

### 7.1 版本风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| V1上线后商家使用率低 | 无法验证产品价值 | 配合人工引导，确保种子商家使用 |
| V2周期性任务打扰商家 | 商家反感，流失增加 | 严格控制推送频率，提供关闭选项 |
| V3与外部系统对接困难 | 功能无法落地 | 提前评估对接难度，预留缓冲时间 |

### 7.2 资源风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 开发资源不足 | 版本延期 | 优先P0功能，P1/P2可延后 |
| 运营内容缺失 | 引导内容质量差 | 提前准备内容，可先用简单版本 |
| 飞书权限申请慢 | 推送功能延期 | 提前申请，准备降级方案 |
| NestJS学习曲线 | 开发效率受影响 | V1启动前安排1周技术预研 |
