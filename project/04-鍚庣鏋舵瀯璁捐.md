## 一、技术选型

### 1.1 唯一推荐方案

**Node.js 20 LTS + NestJS + TypeORM + TypeScript**

| 层级 | 技术 | 版本 |
|------|------|------|
| 运行时 | Node.js | 20 LTS |
| 框架 | NestJS | 10.x |
| ORM | TypeORM | 0.3.x |
| 语言 | TypeScript | 5.x |
| 校验 | class-validator | 0.14.x |
| 转换 | class-transformer | 0.5.x |
| 飞书 SDK | @larksuiteoapi/node-sdk | 最新 |
| 数据库 | MySQL | 8.0 |
| 部署 | PM2 + Nginx | - |

### 1.2 为什么选它

| 理由 | 说明 |
|------|------|
| **前后端同语言** | 前端 Vue 3 + TypeScript，后端 Node.js + TypeScript，类型定义可复用 |
| **NestJS 模块化** | 每个业务域是一个 Module，边界清晰，不会写成一坨 |
| **依赖注入** | Controller → Service → Repository 三层解耦，便于测试和替换 |
| **TypeORM 集成** | NestJS 官方推荐 ORM，TypeScript 实体定义 + Migration 机制成熟 |
| **飞书 SDK 原生支持** | `@larksuiteoapi/node-sdk` 官方维护，对接最顺滑 |
| **200 商家够用** | Node.js 单机轻松承载几千并发，无性能瓶颈 |
| **4-6 周交付 V1** | 脚手架 + 实体自动生成 + CRUD 开发速度快 |

### 1.3 不选其他方案的原因

| 方案 | 不选的理由 |
|------|-----------|
| **Java / Spring Boot** | 200 商家用 Java 太重，启动慢、配置多、编译慢，2-3 人团队 4-6 周搞不定 |
| **Python / FastAPI** | 异步处理不如 Node.js 优雅，前后端 TypeScript 类型无法共享 |
| **Go / Gin** | 性能强但杀鸡用牛刀，学习曲线陡，国内 Go 后端生态不如 Node.js |
| **Express / Koa** | 太自由无约束，业务复杂后代码混乱，不适合业务系统 |
| **PHP / Laravel** | 生态萎缩，TypeScript 类型无法共享 |

## 二、必须遵守的 TypeScript 工程规范

### 2.1 严格模式

```json
// tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

**规则：**
- `strict: true` 必须开启，不允许关闭
- 禁止 `any` 类型，必须明确标注类型
- 禁止未使用的变量和参数

### 2.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | kebab-case | `merchant.service.ts` |
| 类名 | PascalCase | `MerchantService` |
| 接口名 | PascalCase + I 前缀（可选） | `CreateMerchantDto` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 变量/函数 | camelCase | `getMerchantById` |
| 数据库字段 | snake_case | `merchant_id` |
| API 路径 | kebab-case | `/api/merchants` |
| 环境变量 | UPPER_SNAKE_CASE | `DB_HOST` |

### 2.3 导入顺序

```typescript
// 1. Node.js 内置模块
import { join } from 'path';

// 2. 第三方库
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';

// 3. 项目内部模块（绝对路径 @/ 开头）
import { MerchantModule } from '@/modules/merchant/merchant.module';
import { MerchantService } from '@/modules/merchant/merchant.service';

// 4. 类型定义
import type { Merchant } from '@/modules/merchant/entities/merchant.entity';
```

### 2.4 禁止事项

| 禁止 | 原因 |
|------|------|
| 使用 `var` | 作用域问题，必须用 `const` / `let` |
| 使用 `require()` | 必须用 ES Module `import` |
| 使用 `console.log` | 必须用 NestJS Logger |
| 使用 `any` 类型 | 必须明确标注类型 |
| 使用 `enum`（字符串枚举除外） | 数字枚举有隐式转换问题 |
| 在 Service 中直接操作 HTTP 请求 | 应在 Controller 层处理 |
| 在 Controller 中写业务逻辑 | 必须下沉到 Service 层 |

## 三、必须遵守的 NestJS 框架最佳实践

### 3.1 三层架构

```
Controller（接收请求、参数校验、返回响应）
    ↓ 调用
Service（业务逻辑、数据处理）
    ↓ 调用
Repository（数据库操作，TypeORM 提供）
```

**规则：**
- Controller 只做三件事：接收参数、调用 Service、返回响应
- Service 只做业务逻辑，不直接处理 HTTP 请求/响应
- Repository 由 TypeORM 自动注入，不要自己 new

### 3.2 依赖注入

```typescript
// ✅ 正确：通过构造函数注入
@Injectable()
export class MerchantService {
  constructor(
    @InjectRepository(Merchant)
    private readonly merchantRepo: Repository<Merchant>,
  ) {}
}

// ❌ 错误：在 Service 中直接 import 实例
import { merchantRepo } from './merchant.repo';
```

**规则：**
- 所有依赖通过构造函数注入
- 禁止在类内部直接 `new` 其他 Service
- 使用 `@InjectRepository()` 注入 TypeORM Repository

### 3.3 DTO 校验

```typescript
// ✅ 正确：使用 class-validator 装饰器
export class CreateMerchantDto {
  @IsString()
  @IsNotEmpty()
  merchant_id: string;

  @IsOptional()
  @IsString()
  @MaxLength(128)
  nickname?: string;

  @IsEmail()
  email: string;
}

// Controller 中使用
@Post()
create(@Body() dto: CreateMerchantDto) {
  return this.merchantService.create(dto);
}
```

**规则：**
- 所有入参必须定义 DTO 类
- DTO 使用 `class-validator` 装饰器校验
- Controller 使用 `@Body()`、`@Query()`、`@Param()` 装饰器自动校验

### 3.4 异常处理

```typescript
// ✅ 正确：抛出 NestJS 内置异常
throw new NotFoundException('商家不存在');
throw new BadRequestException('参数校验失败');
throw new ConflictException('商家ID已存在');

// ❌ 错误：抛出原生 Error
throw new Error('商家不存在');
```

### 3.5 模块注册

```typescript
// ✅ 正确：模块内部自包含
@Module({
  imports: [TypeOrmModule.forFeature([Merchant])],
  controllers: [MerchantController],
  providers: [MerchantService],
  exports: [MerchantService],  // 需要被其他模块使用时导出
})
export class MerchantModule {}
```

## 四、框架最大化利用原则

### 4.1 NestJS 内置能力必须用

| 能力 | 用法 | 不要自己造轮子 |
|------|------|---------------|
| **Pipe** | `ValidationPipe` 自动校验 DTO | 不要手写 if/else 校验 |
| **Guard** | `AuthGuard` 权限校验 | 不要每个 Controller 手动判断登录 |
| **Interceptor** | 日志、响应格式化、超时处理 | 不要在每个方法里写 try/catch |
| **Filter** | 全局异常捕获 | 不要每个 Controller 都写 exception filter |
| **Decorator** | `@CurrentUser()`、`@Public()` | 不要手写 request.user |
| **Middleware** | 请求日志、CORS、限流 | 不要在 Controller 里写 |

### 4.2 TypeORM 内置能力必须用

| 能力 | 用法 | 不要自己造轮子 |
|------|------|---------------|
| **Entity** | 装饰器定义表结构 | 不要手写 SQL 建表 |
| **Repository** | `this.repo.find()` | 不要手写 SQL 查询 |
| **Migration** | 增量变更数据库 | 不要直接改线上库 |
| **Relation** | `@ManyToOne` 定义关联 | 不要手写 JOIN |
| **SoftDelete** | `@DeleteDateColumn()` 软删除 | 不要手写 WHERE deleted_at IS NULL |

### 4.3 配置管理必须用

```typescript
// ✅ 正确：使用 @nestjs/config
@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,  // 全局可用
      envFilePath: `.env.${process.env.NODE_ENV}`,
    }),
  ],
})
export class AppModule {}

// Service 中使用
constructor(private config: ConfigService) {
  this.dbHost = this.config.get<string>('DB_HOST');
}
```

**规则：**
- 所有配置通过 `ConfigService` 读取
- 禁止在代码中硬编码任何配置值
- `.env` 文件不提交 Git，`.env.example` 提交

## 六、接口响应规则

### 6.1 统一响应格式

```typescript
// 成功响应
{
  "code": 0,
  "message": "success",
  "data": { ... }
}

// 分页响应
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ ... ],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}

// 错误响应
{
  "code": 40001,
  "message": "商家不存在",
  "data": null
}
```

### 6.2 响应拦截器

```typescript
// common/interceptors/response.interceptor.ts
@Injectable()
export class ResponseInterceptor<T> implements NestInterceptor<T, Response<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<Response<T>> {
    return next.handle().pipe(
      map(data => ({
        code: 0,
        message: 'success',
        data,
      })),
    );
  }
}

// 类型定义
interface Response<T> {
  code: number;
  message: string;
  data: T;
}
```

### 6.3 响应规则

| 规则 | 说明 |
|------|------|
| **统一格式** | 所有接口必须返回 `{ code, message, data }` |
| **code = 0 表示成功** | 非 0 表示错误 |
| **data 不嵌套 code/message** | data 是纯业务数据 |
| **分页用 list/total/page/pageSize** | 不要自己定义分页字段 |
| **时间统一用 ISO 8601** | `2026-07-20T10:30:00.000Z` |
| **ID 统一用字符串** | 前端 JS 大数字精度问题 |

### 7.3 异常过滤器

```typescript
// common/filters/http-exception.filter.ts
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse();
    const request = ctx.getRequest();

    let code = ErrorCode.INTERNAL_ERROR;
    let message = '服务器内部错误';
    let status = HttpStatus.INTERNAL_SERVER_ERROR;

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const res = exception.getResponse();
      message = typeof res === 'string' ? res : (res as any).message;
      code = this.statusToCode(status);
    }

    // 记录日志
    this.logger.error(`[${request.method}] ${request.url}`, exception);

    response.status(status).json({
      code,
      message,
      data: null,
    });
  }
}
```

### 7.4 使用规则

| 场景 | 做法 |
|------|------|
| 参数校验失败 | 使用 `class-validator`，自动抛出 `BadRequestException` |
| 资源不存在 | `throw new NotFoundException('商家不存在')` |
| 重复操作 | `throw new ConflictException('商家ID已存在')` |
| 未登录 | `throw new UnauthorizedException()` |
| 无权限 | `throw new ForbiddenException()` |
| 系统异常 | 全局 Filter 捕获，返回 500 |

## 八、日志规则

### 8.1 NestJS Logger

```typescript
// ✅ 正确：使用 NestJS 内置 Logger
import { Logger } from '@nestjs/common';

@Injectable()
export class MerchantService {
  private readonly logger = new Logger(MerchantService.name);

  async create(dto: CreateMerchantDto) {
    this.logger.log(`创建商家: ${dto.merchant_id}`);
    // ...
  }
}
```

### 8.2 日志级别

| 级别 | 用途 | 示例 |
|------|------|------|
| `log` | 正常业务日志 | `创建商家: M001` |
| `warn` | 警告信息 | `飞书推送频率超限: merchant_id=M001` |
| `error` | 错误信息 | `飞书推送失败: merchant_id=M001, error=xxx` |
| `debug` | 调试信息（生产环境关闭） | `查询商家列表: page=1, pageSize=20` |

### 8.3 日志规范

| 规则 | 说明 |
|------|------|
| **禁止 console.log** | 必须用 `Logger`，支持日志级别和格式化 |
| **一个类一个 Logger** | `new Logger(MerchantService.name)`，便于定位 |
| **敏感信息脱敏** | 手机号、token 等不要直接打印 |
| **请求日志统一拦截器** | 不要在每个方法里手动打日志 |
| **错误日志带上下文** | 打印 merchant_id、task_key 等关键参数 |

### 8.4 请求日志拦截器

```typescript
// common/interceptors/logging.interceptor.ts
@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const req = context.switchToHttp().getRequest();
    const { method, url, ip } = req;
    const startTime = Date.now();

    return next.handle().pipe(
      tap(() => {
        const duration = Date.now() - startTime;
        this.logger.log(`${method} ${url} ${duration}ms ${ip}`);
      }),
    );
  }
}
```

## 九、数据库连接方式

### 9.1 TypeORM 配置

```typescript
// src/config/database.config.ts
import { ConfigService } from '@nestjs/config';
import { TypeOrmModuleOptions } from '@nestjs/typeorm';

export const getDatabaseConfig = (config: ConfigService): TypeOrmModuleOptions => ({
  type: 'mysql',
  host: config.get<string>('DB_HOST', '127.0.0.1'),
  port: config.get<number>('DB_PORT', 3306),
  username: config.get<string>('DB_USER', 'root'),
  password: config.get<string>('DB_PASS', 'root123'),
  database: config.get<string>('DB_NAME', 'merchant_task'),
  charset: 'utf8mb4',
  synchronize: false,  // 生产环境永远不要用 synchronize
  logging: config.get<string>('NODE_ENV') !== 'production',
  entities: [join(__dirname, '**', '*.entity{.ts,.js}')],
  migrations: [join(__dirname, '**', 'migrations', '*{.ts,.js}')],
});
```

### 9.2 连接规则

| 规则 | 说明 |
|------|------|
| **synchronize: false** | 生产环境禁止自动同步，必须用 Migration |
| **entities 自动扫描** | 配置 `entities` 路径，TypeORM 自动发现实体 |
| **连接池默认** | TypeORM 默认连接池 10，200 商家足够 |
| **环境变量配置** | DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME |
| **字符集 utf8mb4** | 支持中文和 emoji |

## 十、权限校验入口

### 10.1 飞书登录流程

```
1. 前端跳转飞书授权页
2. 用户授权后，飞书回调携带 code
3. 后端用 code 换取 access_token + user_info
4. 用 feishu_open_id 查询/创建 merchant 记录
5. 签发 JWT token 返回前端
6. 前端后续请求携带 token
```

### 10.2 JWT 认证

```typescript
// common/guards/auth.guard.ts
@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const token = this.extractToken(request);

    if (!token) {
      throw new UnauthorizedException('未登录');
    }

    const payload = this.jwtService.verify(token);
    request.user = payload;  // 挂载到 request
    return true;
  }
}
```

### 10.3 路由保护

```typescript
// 全局守卫（默认所有路由需要登录）
app.useGlobalGuards(new AuthGuard());

// 公开路由使用 @Public() 装饰器跳过校验
@Public()
@Post('auth/feishu/callback')
feishuCallback(@Body() dto: FeishuCallbackDto) {
  return this.authService.feishuLogin(dto);
}
```

### 10.4 权限校验规则

| 规则 | 说明 |
|------|------|
| **默认需要登录** | 全局 AuthGuard，所有路由默认拦截 |
| **公开路由显式声明** | 使用 `@Public()` 装饰器 |
| **权限不足返回 403** | `throw new ForbiddenException()` |
| **Token 过期返回 401** | `throw new UnauthorizedException()` |
| **当前版本只区分登录/未登录** | V2 再加角色权限 |
