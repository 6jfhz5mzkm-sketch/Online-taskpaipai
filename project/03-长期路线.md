### 3.2 第二阶段：智能期（V3-V4）

**核心能力：智能推荐 + 分层运营 + 数据分析**

#### V3（营销投放+数据分析）

| 模块 | 功能 | 状态 |
|------|------|------|
| 营销任务 | 投放、活动、内容任务 | ✅ 本期实现 |
| 数据任务 | 数据分析引导任务 | ✅ 本期实现 |
| 任务推荐（进阶版） | 基于行为+标签推荐 | ✅ 本期实现 |
| 商家分层 | 基于完成度分层 | ✅ 本期实现 |
| **数据分析专区** | **店铺数据上传 + 数据看板 + AI 经营分析** | ✅ 本期实现 |

> **数据分析专区规划（v1.3 补充，依据《数据分析专区方案》v2.0）**：
> - **店铺数据上传（独立模块）**：6 个数据任务（stage_id = `shopdata`，从阶段二 T2.5 剥离而来），任务数据留库、进度单独记录；独立解锁——完成阶段二「商品发布」（T2.2，listing）全部任务后解锁，无需等待阶段二全部完成
> - **数据看板**：商家经营数据展示（指标卡片 + 时间维度切换）
> - **AI 经营分析**：与数据看板同页一体，后端 `ai` 模块 + 每日限流 + 缓存
> - **复用路径**：专区直接复用阶段二剥离出的数据模块（`shop_*` 表、`/api/shop/*` 与 `/api/shop/analysis` 接口、DataForm / ExcelUpload 组件），数据层零重复建设；专区结构预留扩展（经营周报、健康评分等新卡片），并与阶段三「数据分析引导任务」可自由绑定（数据与任务已解耦）

### 5.3 技术栈适用边界（长期视角）

#### 当前技术栈持续适用的条件

| 条件 | 说明 | 当前状态 |
|------|------|---------|
| 商家规模 ≤ 5000家 | 单机Node.js + MySQL可承载 | ✅ 2000家 |
| 日活 ≤ 500 | 无并发压力 | ✅ 预估200 |
| 业务逻辑中等复杂度 | NestJS模块化可良好组织 | ✅ 任务体系 |
| 团队规模 2-5人 | TypeScript统一技术栈 | ✅ 2-3人 |

#### 什么情况下需要重新评估技术路线

| 触发条件 | 当前技术栈的瓶颈 | 建议调整 | 优先级 |
|---------|-----------------|---------|--------|
| **商家规模 > 10000家** | Node.js单线程可能成为瓶颈 | 热点服务迁移到Go/Java | 中 |
| **日活 > 2000** | 需要考虑水平扩展 | 引入负载均衡 + 数据库读写分离 | 中 |
| **业务逻辑极度复杂** | NestJS模块化可能不够 | 评估是否需要微服务拆分 | 低 |
| **团队 > 10人** | 前后端协作成本增加 | 考虑BFF层或GraphQL | 低 |
| **需要实时通信** | 当前架构不支持WebSocket | 引入WebSocket服务 | 低 |
| **需要复杂数据分析** | MySQL分析查询性能有限 | 引入ClickHouse/Elasticsearch | 低 |
| **需要AI/ML能力** | Node.js不适合 | Python服务独立部署 | 低 |

#### 技术栈迁移成本评估

| 迁移方向 | 成本 | 建议时机 |
|---------|------|---------|
| Vue 3 → React | 高（前端重写） | 除非团队全部转React |
| NestJS → Spring Boot | 高（后端重写） | 除非需要Java生态 |
| Node.js → Go | 中（热点服务迁移） | 商家规模 > 5000时 |
| MySQL → PostgreSQL | 低（数据迁移） | 需要高级SQL特性时 |
| 单体 → 微服务 | 高（架构重构） | 业务复杂度显著增加时 |

## 十、总结

### 10.1 核心原则

1. **小步快跑**：每个版本快速验证，不追求一步到位
2. **数据驱动**：每个版本都要有量化指标，用数据决策
3. **商家导向**：所有功能设计以商家实际需求为中心
4. **可持续演进**：架构和功能设计要为后续扩展留空间

### 10.2 关键成功因素

1. **种子商家的成功**：V1要确保有一批商家成功走完全流程
2. **数据闭环**：从数据采集到数据应用要形成闭环
3. **运营配合**：任务体系需要运营持续优化内容和策略
4. **技术稳定性**：H5页面和飞书推送要稳定可靠

### 10.3 下一步行动

1. 确认V1功能范围和优先级
2. 完成技术方案评审
